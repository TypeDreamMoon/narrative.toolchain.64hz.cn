# DNS2xxx — 解析器 [#dns2xxx--parser]

## DNS2001 [#dns2001]

这一行缩进在一个不开启块的行下面。

**说明：**像 `dialogue`、`if` 和选项这样的块头下面可以有嵌套内容，而 `set`、`->` 和属性这类叶子行下面不能。要么把这行减少缩进，要么把它放到它本该属于的块头下面。文件第一行就缩进也会触发这个错误码。对话和旁白是例外：更深的纯文本行会延续同一句台词。

## DNS2002 [#dns2002]

块头下面没有内容。

**说明：**像 `if`、`else`、`journal`、`on accept` 和轨道名这样的块头要求下面有更深的内容。空块通常意味着漏写了内容或缩进写错了。补上内容，或者删掉这个块头。空的选项（例如 `- Goodbye` 后面不执行任何动作）是允许的。

## DNS2003 [#dns2003]

这一行放错了地方。

**说明：**每个块只接受特定类型的行：顶层只接受声明，`quest` 里只接受任务属性，`stage` 里只接受轨道。这一行和它所在的位置对不上，最常见的原因是缩进少了一级。检查它的缩进和关键字。

## DNS2004 [#dns2004]

同一个修饰符在一行里出现了两次。

**说明：**每种后缀最多只能出现一次：一个 `if`、一个 `once`、一个 `#id`。重复写同一个后缀会让优先级变得不明确。只保留一个。

## DNS2005 [#dns2005]

选项出现在对话之外。

**说明：**以 `- ` 开头的行是玩家选项，只能出现在 `dialogue` 块里，包括它嵌套的 `if` 或选项体。在顶层或任务块里遇到它，通常说明缩进丢了。把它缩回对话里。

## DNS2006 [#dns2006]

对话里的 ` if ` 被当作了普通文本（提示）。

**说明：**行尾的 `if` 只有在后面的内容能解析成条件、并且条件里引用了至少一个已声明的名字时，才算条件修饰符；否则它仍是台词的一部分。如果本意是写条件，检查名字有没有声明、表达式语法有没有写对；如果本意就是台词内容，可以忽略这条提示，或者把整句用引号包起来让它不再出现。

## DNS2007 [#dns2007]

解析器期望某个东西，却遇到了别的。

**说明：**这个通用语法错误涵盖这些情况：`if` 后面缺少条件、`fact Name:` 后面不是合法类型、`wait` 后面缺少时长、括号没有配对等。消息里会说明期望什么、实际遇到什么。按消息补上或改正那部分。

## DNS2008 [#dns2008]

一行或一个表达式已经完整，后面却还有多余的内容。

**说明：**`set x = 1 2` 里的 `2`，或者 `-> Node` 后面多出来的词，在语法上都没有位置。检查是不是少了运算符，或者多余的部分本该写在下一行。

## DNS2009 [#dns2009]

这种行不允许这个修饰符。

**说明：**行尾的 `once` 只属于选项；对话头上的 `once` 管的是入口，而不是这一条。`for Duration` 和 `@Stage` 只属于对话和旁白行。放错位置的修饰符会被记录下来，但不会生效。删掉它，或者把它挪到支持它的行上。

## DNS2010 [#dns2010]

`else` 前面没有 `if`。

**说明：**`else` 和 `else if` 必须紧跟在同一层级的 `if` 或 `else if` 之后。中间隔了一句台词，或者连续写了两个 `else` 子句，都会断开这条链。调整行的顺序，或者把中间的内容挪进分支里。

## DNS2011 [#dns2011]

任务的 `priority:` 只能是 main、side 或 hidden。

**说明：**`main` 标识主线任务，默认会检查它是否会被卡死；`side` 标识支线任务；`hidden` 是不给玩家看的记账任务，比如一串线索。写成别的词没有定义的行为。请从这三个值中选一个。

## DNS2012 [#dns2012]

任务的 `timeout:` 必须是一个时长。

**说明：**超时从接受任务那一刻开始计时。写一个正数并跟上单位，例如 `20m`、`90s`、`1.5h` 或 `300ms`。它走的是叙事时钟，游戏暂停时停止。其他形式、零和负数都不能构成有效的超时。

## DNS2013 [#dns2013]

任务的 `on` 块里不能 `wait`。

**说明：**`on accept`、`on complete` 这类块在任务发生变化时同步执行完，没有挂起后继续的地方。需要等待的动作放进对话，或者用 `play` 请游戏播放一段演出。

## DNS2014 [#dns2014]

一个任务最多只能有 31 个目标。

**说明：**已锁存的目标被记在一个整数的各个位上。如果任务超出这个容量，就把它拆成几个 `subquest` 块，各自带日志和奖励，这样玩家也更容易看清进度。

## DNS2015 [#dns2015]

频道的属性无效。

**解释：**频道策略包括 `input`（lock / free）、`advance`（player / auto）、`busy`（queue / interrupt / drop）、`stage`（pause / continue），以及逗号分隔的 `pauses` / `stops` 列表。写了未知的属性名、取值不合法或列表为空，都会报这个码。一个频道不能暂停或停止自己；自身冲突由 `busy` 决定。它也不能停止 `main`，后者属于玩家正在进行的对话。要让主对话期间其他频道安静下来，改为在 `channel main` 上声明 `pauses`。

## DNS2016 [#dns2016]

`channel main` 只能改 `pauses` 和 `stops`。

**解释：**主频道锁定输入、等待玩家，并在新对话开始时替换掉旧对话，这三条是它的定义。想要一个不锁输入、自动推进的频道，就另外声明一个，并用 `channel Name` 把对话放上去。

## DNS2017 [#dns2017]

一段对话不能既是角色入口（`for`）又是事件入口（`on`）。

**解释：**角色入口在玩家和该角色说话时被选中；事件入口在事件抛出时被选中。两者合在一起会让触发时机变得含糊。拆成两段对话，需要时用 `->` 共享第三段对话。

## DNS2018 [#dns2018]

自动频道上的对话不能有选项。

**解释：**`advance: auto` 频道按每行的时长自动推进，不等待玩家选择。选项会让它一直卡住。把需要交互的对话移到 `advance: player` 频道上（例如 `main`），或者去掉选项。

## DNS2019 [#dns2019]

事件参数只能写类型、集合、范围和默认值。

**解释：**参数看起来和 fact 一样，例如 `数量: int range 1..9 = 1`，但没有存档状态、归属或改名历史。诸如 `extern`、`session`、`profile`、`progress`、`was` 和 `gameplay` 这类只属于 fact 的修饰符不该写在参数上。删掉这些修饰符；如果某个值必须由游戏拥有并持久化，就声明成 fact。

## DNS2020 [#dns2020]

`emit` 里同一个参数写了两次。

**解释：**`emit 发现敌人(数量 = 1, 数量 = 2)` 说不清到底要发出去的是哪个值。每个参数最多写一次。省略的参数取声明里的默认值。

## DNS2021 [#dns2021]

由 gameplay 标签提供的 fact 必须是 `extern`。

**解释：**`fact Name: bool extern gameplay Tag` 镜像玩家能力系统上的一个标签。GAS 桥以游戏的身份写入，所以剧情不能拥有这个 fact。加上 `extern`；如果这个值该由剧情控制，就去掉 `gameplay`。

## DNS2022 [#dns2022]

参数写了 `from`，但它的事件没有 `gameplay` 映射。

**解释：**`from magnitude` 和 `from target tags Tag` 读取 GameplayEvent 的载荷。只有用 `gameplay Tag` 声明并通过桥抛出的事件才有这样的载荷。给事件补上它的 gameplay 标签；如果只有游戏代码或剧情会抛出它，就删掉 `from`。

## DNS2023 [#dns2023]

一个 fact 只能占用一种存储范围。

**解释：**默认是存档槽；`session` 只活在当前会话里，不进存档；`profile` 有单独一份跨存档槽、跨周目的快照。这些范围互斥。`progress` 是存档槽里的细分：选章时保留它的值，检查点则省略它。它不能与 `session` 或 `profile` 组合。分组上的修饰会作用于组里的每一项，冲突报在受影响的那一项上。

## DNS2024 [#dns2024]

一份资料库最多 31 条。

**解释：**已解锁的条目占用一个整数的各个位。更大的资料库可以按章节、武器等级或其他有用的分组拆开，既放得进这种表示方式，玩家翻起来也更容易。
